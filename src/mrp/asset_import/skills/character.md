# 人物角色卡整理

从原稿整理一张人物卡，只提取原稿明确给出的事实，不补写经历、关系、外貌、台词或能力。目标是**保留信息并重组字段**，不是把原稿缩写成简介。世界公共设定无需在每张人物卡全文重复。模型、API、头像路径、作者与运行参数由系统或用户管理。

字段分工：
- `description` 写身份、经历和关系，不要把能力体系挤在简介末尾。
- `appearance` 是独立的身体与外貌字段。原稿写了体态、年龄呈现、发色、眼睛、衣着、辨识特征或稳定形态时，逐项保留具体信息；没有资料才留空，不要用“美丽”“神秘”等空泛词代替。形态变化中的外观规则也放这里，不要误写成已发生剧情。不要将未成年形态与成人性内容关联或补写。
- `traits_label` 与 `traits` 是可自定义标题的核心特质栏。奇幻角色通常使用“能力与实力”；其他题材可使用“专业技能”“专长与装备”或更贴合原稿的标题。保留原稿中的具体技能、实力等级、数值、使用条件、代价和限制，不得压成一句概述；没有相关信息时正文留空，不要为日常角色编造超能力。
- `personality` 写性格、动机、矛盾、行为倾向及其成因。原稿每个明确的小标题或性格要点都要有对应内容，保留“全知但不懂亲密”这类张力与限制；不要合并成几句泛泛评价。
- `scenario` 只写开场时的情境与关系；`first_mes` 和 `mes_example` 只有原稿提供了可直接使用的台词时才填写。

写法：这是供模型读取的人设资料，用角色名字或小标题建立主语，然后写清楚事实；避免每句话都以“她/他”开头，也不要整张卡写成“我是……”的独白。只有角色亲口说出的开场白或对话示例才用第一人称。保留原稿独有的外貌、特质与性格细节，不机械复述，也不把重要细节压成一句泛泛概括。输出前逐项检查原稿标题和要点是否已经落入 `description`、`appearance`、`traits` 或 `personality`，不要因 JSON 较长就删掉后半部分。

输出必须是单个 JSON 对象，字段严格符合随任务提供的 schema，不要 Markdown 或解释。
